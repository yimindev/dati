## US-02：配置数据访问范围

### 使用场景

管理员在创建服务时即可配置数据范围（创建弹窗内选择器），也可进入 MCP 服务详情页的「数据范围」Tab 随时调整。数据范围为服务所必需的访问边界，配置后 Tool 的元数据检索和 SQL 执行都受此范围约束。

### 交互流程

```
创建弹窗（数据范围必填）/ 详情页「数据范围」Tab
  ├─ 共用同一个选择器（ScopePicker 组件）：
  │    ├─ [+ 添加数据源] → 下拉列表选择数据源（从已有 DataSource 列表获取）
  │    └─ [+ 添加主题] → 下拉列表选择主题（从已有 Subject 列表获取）
  │
  ├─ 已选范围列表：
  │    ├─ 每项显示：类型图标 + 名称 + [删除]
  │    ├─ 数据源项：图标+"数据源名称"
  │    └─ 主题项：图标+"主题名称" + 「引用模式，自动同步」提示
  │
  └─ [保存] 按钮
```

### 异常与边界

- 选的数据源后来被删了：保存时不校验数据源是否存在（引用可能失效），执行 Tool 时再报错
- 主题引用自动同步：主题增删表，服务范围自动变化，不需要管理员重新保存
- 重复添加：不阻止（前端可做提示但非强制）
- 已发布服务修改数据范围：保存到草稿副本，需重新发布才生效（见 US-08）

### 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `PUT` | `/v1/mcp-services/{id}/data-scope` | 全量替换保存。Body: `{ items: [{ type, referenceId, referenceName }] }`。返回 `IdResponse` |
| `GET` | `/v1/mcp-services/{id}/data-scope` | 查询当前数据范围。返回 `{ items: [...] }`。主题类型额外返回展开的表列表（仅用于前端展示） |
| `GET` | `/v1/data-sources?type=scope_selector` | 可选数据源列表（复用 DataSourceController） |
| `GET` | `/v1/subjects?type=scope_selector` | 可选主题列表（复用 SubjectController） |

### 前端设计

- 两种添加方式用一个下拉按钮（Split Button），默认展示常用添加方式
- 已选范围列表：区分两种类型的视觉展示（不同图标 + 不同颜色标签）
- 主题项 hover 展示「主题内的表：table_a, table_b, ...」

### 数据库设计

**`mcp_service_data_scope` 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR | 主键 |
| `service_id` | VARCHAR | FK → mcp_service.id |
| `scope_type` | VARCHAR(20) | DATA_SOURCE / SUBJECT |
| `reference_id` | VARCHAR(255) | 数据源 ID / 主题 ID |
| `reference_name` | VARCHAR(255) | 冗余名称，用于展示 |

索引：`(service_id)`

### 安全设计

- 通过服务 ID 校验操作权限（属于当前租户/用户）
- 数据源列表和主题列表复用已有接口的权限过滤

### 验收标准

1. 添加数据源后，已选列表展示数据源名称
2. 添加主题后，已选列表展示主题名 + 引用模式说明
3. 保存后，再次进入范围 Tab 看到之前的选择
4. 主题引用后，在 DatI 中修改了主题关联的表，MCP 服务的数据范围自动更新
