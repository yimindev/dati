## US-05：创建与配置 Prompt

### 使用场景

管理员进入「Prompts」Tab，编写 Prompt 模板文本（使用 `{{paramName}}` 占位），定义参数列表。Prompt 暴露给 MCP Client 后，Client 通过 `prompts/get` 获取替换后的文本，供 Agent 作为上下文/系统提示使用。

### 交互流程

```
Prompts Tab
  ├─ Prompt 列表
  │    ├─ 列：name、参数数量、启用开关、操作（编辑/删除）
  │    └─ [新建 Prompt] 按钮
  │
  └─ 编辑表单：
       ├─ name（文本框，必填，格式 [A-Za-z0-9_.-]{1,128}，服务内唯一）
       ├─ description（文本框，可选）
       ├─ content（Textarea）—— 支持 {{paramName}} 语法，等宽字体
       ├─ 参数列表（动态表格）：
       │    ├─ 列：参数名 / 描述 / 必填（复选框）
       │    └─ [+ 添加参数] [删除]
       ├─ [测试渲染] 按钮（纯前端：解析 {{param}} 生成输入表单 → 填入 → 展示替换结果）
       └─ [保存]
```

保存时前后端均校验：
1. 通过模板引擎 `TemplateParser.parse(content)` 检测模板语法错误（未闭合 `{{` 等），有错则拒绝保存
2. 通过 `CompiledTemplate.getVariables()` 提取 content 中所有参数名
3. 与 `arguments` 中定义的参数名双向比对，不一致则拒绝保存并提示具体不匹配的参数名

### 异常与边界

- name 格式不合法：实时校验提示「仅允许 A-Z, a-z, 0-9, _, -, .，1-128 字符」
- name 重复：保存时后端校验，返回「Prompt 名称已被使用」
- name 为空：前端校验必填
- content 中 `{{xxx}}` 未在参数列表中定义：前后端校验（通过模板引擎 `getVariables()` 比对），返回「参数 `xxx` 未定义」
- 参数列表中 `yyy` 未在 content 中引用：前后端校验，返回「参数 `yyy` 在模板中未使用」
- content 模板语法错误（如 `{{` 不闭合）：保存时后端通过 `TemplateParser.parse()` 检测并拒绝，返回具体错误原因
- 删除 Prompt：确认弹窗
- 已发布服务修改 Prompt：保存到草稿副本，需重新发布

### 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/v1/mcp-services/{id}/prompts` | 查询 Prompt 列表 |
| `POST` | `/v1/mcp-services/{id}/prompts` | 创建 Prompt |
| `PUT` | `/v1/mcp-services/{id}/prompts/{promptId}` | 编辑 Prompt（含 enabled 开关） |
| `DELETE` | `/v1/mcp-services/{id}/prompts/{promptId}` | 删除 Prompt |

保存时后端校验逻辑：
1. 调用 `TemplateParser.parse(content)` 检查模板语法
2. 通过 `CompiledTemplate.getVariables()` 提取 content 中所有变量名
3. 从 arguments 中提取所有参数名
4. 两个集合必须完全一致，否则返回具体的不匹配参数名

### 前端设计

- content 编辑区支持 `{{paramName}}` 的高亮显示（与普通文本颜色不同）
- 参数列表为小型内联表格
- 测试渲染纯前端实现：解析 content 中 `{{param}}` → 生成输入表单 → 用户填入值 → 实时展示替换结果
- 参数列表变更时，前端同步校验 content 和参数的一致性（warning 提示而非阻止保存，最终由后端兜底）
- 启用开关通过 PUT 更新 `enabled`，即时生效

### 数据库设计

**`mcp_prompt` 表**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR | 主键 |
| `service_id` | VARCHAR | FK → mcp_service.id |
| `name` | VARCHAR(128) | Prompt 名称（服务内唯一，格式 [A-Za-z0-9_.-]{1,128}） |
| `description` | VARCHAR(500) | 描述（可选） |
| `content` | TEXT | Prompt 文本模板，`{{paramName}}` 占位 |
| `arguments` | TEXT(JSON) | 参数列表：`[{name, description, required}]` |
| `enabled` | BOOLEAN | 是否启用 |
| 审计字段 | — | 继承 BasePO |

索引：`UNIQUE(service_id, name)`，`(service_id)`

### MCP 协议映射

保存到 MCP `prompts/list` 响应时：
- `name` ← DB.name
- `description` ← DB.description
- `arguments` ← DB.arguments 解析为 `[{name, description, required}]`

MCP `prompts/get` 渲染时：调用 `TextRenderer.render(parsed, params)`，将 arguments 参数值替换到 content 中所有 `{{paramName}}` 占位。

**模板引擎集成**：Prompt 模板的解析和渲染使用 `com.dati.common.template` 模板引擎（见 US-5.5），替代原来的手写正则提取和字符串替换。语法与 US-03 的 SQL 模板统一使用 `{{paramName}}` 占位。

### 安全设计

- Prompt 文本不做注入检测（MCP Client 侧负责安全使用）
- 测试渲染仅前端实现，不给后端发测试数据

### 验收标准

1. 创建 Prompt，name 为「analyze_table」，content 写「请分析 {{table}} 表的数据」，添加参数 `table`（必填），保存成功
2. 测试渲染（前端），输入 table=tasks，渲染结果中 `{{table}}` 被替换为 `tasks`
3. content 中写了 `{{status}}` 但参数列表未定义，保存时后端返回错误「参数 `status` 未定义」
4. 参数列表中定义了 `limit` 但 content 中未引用，保存时后端返回错误「参数 `limit` 在模板中未使用」
5. 创建同名 Prompt 时报错「Prompt 名称已被使用」
6. 删除 Prompt 后列表不再显示
