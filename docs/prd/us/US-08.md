# US-08：发布、停用与版本管理 MCP 服务

## 使用场景

管理员完成 Tool / Prompt / 数据范围配置后，在「调试发布」Tab 预览能力列表，校验配置后发布服务。发布后获得 endpoint，可复制给 MCP Client 使用。支持停用、重新启用、历史版本回滚。

已发布服务如修改配置（Tool/Prompt/数据范围/基础信息），线上继续服务旧版本，修改保存到草稿副本，需重新发布才覆盖。

## 核心模型

### 草稿区（Draft Config）

持久化的实时配置数据表（服务基础信息、Data Scope、Prebuilt Tools、Custom Tools、Prompts）。用户自由修改，自动保存，不影响线上服务。

### 快照与激活指针

- 发布时全量打包草稿生成**只读快照**（`mcp_service_snapshot`），版本号严格单调递增（v1, v2, v3...），记录 release_note
- 服务上的 `active_version_id` / `active_version_number` 指向当前对外响应的快照
- MCP endpoint 仅读取激活快照，不直接访问草稿数据

### 状态机

| 状态 | 含义 |
|------|------|
| `DRAFT` | 新建后从未发布过 |
| `PUBLISHED` | 线上正常对外响应 |
| `DISABLED` | 已下线，保留激活快照指针与全部配置 |

**合法转换（含前置条件校验）：**

| 操作 | 合法转换 | 非法时 |
|------|----------|--------|
| publish | DRAFT→PUBLISHED；PUBLISHED→PUBLISHED；DISABLED→**DISABLED** | — |
| disable | 仅 PUBLISHED→DISABLED | DRAFT / DISABLED 报错 |
| enable | 仅 DISABLED→PUBLISHED | DRAFT（无激活快照）报错 |
| rollback | 需已存在目标版本快照 | 目标版本不存在报错 |

> **发布 ≠ 上线**：DISABLED 状态下发布只更新快照，不改变状态。停用期间改配置发布后，服务仍保持停用，需手动启用才恢复对外。

## 交互流程

### 详情页右上角（服务级状态操作区，全 Tab 可见）

| 服务状态 | 按钮组 |
|----------|--------|
| `DRAFT` | [发布] |
| `PUBLISHED` | [发布变更]（仅 has_changes 时，hover 弹变更摘要）+ [停用] |
| `DISABLED` | [启用] + [发布变更]（仅 has_changes 时） |

- 「发布变更」按钮 hover 弹出变更摘要 popover：Tools `+新增 ~修改 -删除` 名称列表 / Prompts / 数据范围 / 基础信息，超过 5 项截断提示
- 发布弹窗内嵌「将发布以下变更」摘要区（完整列表），下方 release note 输入 + 确认
- 删除入口统一在列表页（详情页不提供）

### 版本管理 Tab

```
版本管理 Tab（原「调试发布」）
  ├─ 头部：当前线上版本 Tag（vN）+ MCP Endpoint（复制按钮）
  └─ 版本快照历史表格：
       ├─ 版本号（当前激活带 Live Tag）+ Release Note + 更新时间
       ├─ [回滚] 按钮 → 确认弹窗「将回滚至 vN，当前未发布的草稿修改将被 vN 内容覆盖，确定吗？」
       └─ 回滚后：草稿 = 线上 = vN 内容，diff 无变化，历史中新增 vN+1（内容等于 vN，Release Note 为 "Rollback to vN"）
```

### 变更感知三级递进（共用页面级 diff 数据）

1. **感知**：右上角「发布变更」按钮 hover → popover 摘要（截断 5 项）
2. **确认**：发布弹窗内 → 完整变更摘要 + release note + 确认发布
3. **深度**：版本管理 Tab（历史版本、回滚）

任何草稿修改（基础信息保存 / Tool / Prompt / 数据范围增删改）保存后，页面级 diff 自动刷新，「发布变更」按钮实时出现。

## 异常与边界

- 发布前无任何 Tool/Prompt：允许发布（纯空服务）
- 发布后无启用状态的 Tool：MCP Client 的 tools/list 返回空数组
- 停用后 MCP Client 调用：MCP endpoint 返回明确错误（JSON-RPC error + HTTP 503）
- 启用后立即恢复对外服务，无需重新发布
- DRAFT 状态 enable / disable：报错（无激活快照，状态转换非法）
- 编辑 → 草稿 → 未发布就离开：草稿自动保存，下次进入时恢复
- 回滚目标版本不存在：报错，草稿与线上均不变

## 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/v1/mcp-services/{id}/publish` | 发布。打包草稿生成快照 vN+1 并激活。DRAFT→PUBLISHED，DISABLED 时保持 DISABLED。Body：`{ "release_note": "..." }`（可选） |
| `POST` | `/v1/mcp-services/{id}/rollback` | 回滚。目标快照内容全量写回草稿（基础信息/Data Scope/Tools/Prompts），再生成新快照 vN+1。Body：`{ "target_version_number": 1, "release_note": "..." }`（可选） |
| `POST` | `/v1/mcp-services/{id}/disable` | 停用。仅 PUBLISHED→DISABLED，不产生新快照 |
| `POST` | `/v1/mcp-services/{id}/enable` | 启用。仅 DISABLED→PUBLISHED，不产生新快照 |
| `GET` | `/v1/mcp-services/{id}/snapshots` | 历史版本快照列表，倒序（版本号、Release Note、创建时间） |
| `GET` | `/v1/mcp-services/{id}/diff` | 草稿 vs 激活快照差异摘要（基础信息/Data Scope/Tools/Prompts 变更明细 + hasChanges）。**仅比较业务字段**（配置内容），排除 id 与审计字段（created_at/updated_at 等）—— 快照反序列化不保留审计字段、回滚恢复会刷新时间戳，全字段比较必然误报。prebuilt 配置变更并入 `modified_tools`（工具名 = toolType） |

> 设计说明：发布/回滚/启停均用显式动词端点，与 UI 操作一一对应；不将发布与回滚合并进 `POST /snapshots`（两者副作用不同），也不用 `POST /toggle {enabled}`（boolean 无法表达状态机前置条件）。

## 前端设计

- 详情页右上角为服务级状态操作区（发布/发布变更/停用/启用），全 Tab 可见；操作结果统一刷新页面级 service + diff
- 变更摘要组件 `DiffSummaryList`（popover 与发布弹窗共用，props 控制截断）：分组分隔线 + 语义色 tag（mono 字体展示工具名）+ 截断提示
- 版本管理 Tab：版本 Tag + Endpoint 复制 + 版本历史表格（Live Tag / Release Note / 回滚）
- 回滚确认弹窗必须明示破坏性：当前未发布的草稿修改将被目标版本覆盖
- 停用状态下发布成功 → 提示「服务仍处于停用状态，需启用才对外服务」
- i18n 全覆盖（zh/en），组件内无硬编码文案

## 数据库设计

**快照表方案（定稿）：** 独立的 `mcp_service_snapshot` 表，发布时全量序列化草稿为 JSON 存入。草稿仍读原表，MCP endpoint 只读快照表。

## 安全设计

- 发布/回滚/停用/启用仅管理员可操作
- 发布/回滚/启停记录操作人和时间（快照记录 release_note；服务状态变更走 update 审计字段）

## 验收标准

1. 配置 Tool 后，在 Tools Tab 看到工具列表；右上角出现「发布」按钮
2. 点击发布，状态变为「已发布」，展示 endpoint URL 和接入信息
3. 复制 endpoint URL，用外部 MCP Client 连接成功，tools/list 返回已启用 Tool
4. 修改 Tool 配置后保存，右上角出现「发布变更」按钮，hover 可见变更摘要（Tools +1 等）
5. 外部 MCP Client 仍看到旧版本 Tool（线上不受影响）
6. 点击发布变更，外部 MCP Client 看到新版本 Tool
7. 停用服务，外部 MCP Client 调用返回错误；启用后恢复（无需重新发布）
8. 停用状态下发布变更：状态保持停用，外部 MCP Client 仍返回错误
9. 回滚至 v1：外部 MCP Client 看到 v1 的 Tool 配置；编辑器（草稿）与线上一致；diff 无变更；快照历史新增 "Rollback to v1" 记录
10. 从未发布（DRAFT）的服务调用 enable / disable：返回错误
11. 回滚到不存在的版本：返回错误，线上与草稿均不变

## 遗留任务（不在本期范围）

本期发布能力聚焦**数据版本化**（草稿 → 快照 → 版本管理 → 回滚），MCP 服务本身尚未真正对外暴露：

1. **MCP Endpoint 实现**：`/{code}/mcp` 的 JSON-RPC / SSE 接口（`initialize` / `tools/list` / `prompts/list` / `tools/call` 等）尚未实现，当前 endpoint 仅存在于配置层面
2. **快照消费**：MCP endpoint 需只读激活快照（`active_version_id`）响应请求，不直接访问草稿数据 —— 需在 endpoint 实现时落地
3. **停用语义**：DISABLED 状态下 MCP Client 调用应返回明确错误（JSON-RPC error + HTTP 503）
4. **空服务语义**：发布后无启用 Tool 时 `tools/list` 返回空数组
5. **依赖上述实现的验收标准**：第 3（外部 Client 连接）、5/6（线上版本隔离与覆盖）、7/8（停用/启用后的可见性）、9（回滚后的线上内容）

> 上述能力建议作为独立 US（如 US-09 MCP Endpoint）立项，本期验收标准中涉及外部 MCP Client 的条目在 Endpoint 实现前视为「待验证」。
