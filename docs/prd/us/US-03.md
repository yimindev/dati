## US-03：创建与配置 Tool

### 使用场景

管理员进入「Tools」Tab，查看和配置两类工具：

- **预置工具（3 种）**：系统内置的 `SEARCH_METADATA`、`GET_TABLE_INFO`、`EXECUTE_SQL`，所有服务共享同样的名称、描述和输入参数定义。管理员只需决定开关和调参（如 `EXECUTE_SQL` 的权限策略、超时、行数限制）。预置工具不可删除、不可改名。
- **自定义工具**：用户创建的参数化 SQL 工具（`PARAMETERIZED_SQL`），每个服务可创建多个。管理员自行定义名称、描述、SQL 模板和参数。

`annotations` 和 `inputSchema` 由 MCP 协议适配层按需生成，管理端不展示也不存储。

### 交互流程

```

  ├─ 预置工具区
```

### 异常与边界

- name 格式不合法：实时校验提示「仅允许 A-Z, a-z, 0-9, _, -, .，1-128 字符」
- name 重复：保存时后端校验，返回「Tool 名称已被使用」（仅自定义工具；预置工具无此概念）
- 预置工具不可删除、不可改名
- PARAMETERIZED_SQL 的 SQL 模板语法错误：分两类处理——
  - **模板语法错误**（`{{` 不闭合、`{{#if}}` 缺 `{{/if}}`、未知指令等）：**保存时拒绝**，通过模板引擎 `TemplateParser.parse()` 检测，返回具体错误原因
  - **SQL 语法错误**（拼错关键字、表不存在等）：**执行时报错**（不同数据库方言不同，保存时不校验）
- PARAMETERIZED_SQL 参数名未在 SQL 模板中引用 / 模板中引用了未定义的参数：**保存时强校验**，通过模板引擎 `CompiledTemplate.getVariables()` 与 `parameters[]` 双向比对，不一致则拒绝保存并返回具体不匹配的参数名
- 删除自定义工具：确认弹窗，提示「删除后 MCP Client 将无法调用此工具」
- 已发布服务修改 Tool：保存到草稿副本，需重新发布

### 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/v1/mcp-services/{id}/tools` | 全量列表，按预置/自定义分组返回 |
| `PUT` | `/v1/mcp-services/{id}/tools/{toolId}` | 更新工具（含 enabled 开关） |
| `POST` | `/v1/mcp-services/{id}/tools` | 创建自定义工具 |
| `DELETE` | `/v1/mcp-services/{id}/tools/{toolId}` | 删除自定义工具 |
| `POST` | `/v1/mcp-services/{id}/tools/{toolId}/test` | 调试执行（US-07 实现） |

`toolId` 取值：
- 预置工具：`SEARCH_METADATA`、`GET_TABLE_INFO`、`EXECUTE_SQL`

### 前端设计

- 接口返回分组数据（`prebuilt` + `custom`），前端直接按区域渲染，无需判别字段
- 预置工具区：只读卡片行，仅开关 + EXECUTE_SQL 的配置按钮；不可删除、不可改名
- 自定义工具区：标准表格 + 新建按钮（单一入口，不再需要类型选择下拉）
- 新建/编辑弹窗为 Modal，字段较多可用分段折叠（通用 → SQL/参数 → 执行限制）
- SQL 模板编辑器：等宽字体、`{{}}` 语法，可用 Monaco/CodeMirror 的 Handlebars 模式高亮
- Annotations 预览：纯前端根据 `perm_config` 计算，展示在弹窗中供参考
- 启用开关即时生效：前端直接调 PUT 更新 `enabled`

### 数据库设计

**`mcp_prebuilt_tool_config` 表**（预置工具 per-service 配置）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR | 主键 |
| `service_id` | VARCHAR | FK → mcp_service.id |
| `tool_type` | VARCHAR(30) | SEARCH_METADATA / GET_TABLE_INFO / EXECUTE_SQL |
| `enabled` | BOOLEAN | 是否启用，默认 true |
| `config` | TEXT(JSON) | 配置对象，null 时使用枚举中的默认值 |
| 审计字段 | — | 继承 BasePO |

索引：`UNIQUE(service_id, tool_type)`

**`mcp_custom_tool` 表**（自定义工具）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR | 主键 |
| `service_id` | VARCHAR | FK → mcp_service.id |
| `name` | VARCHAR(128) | Tool 标识（服务内唯一，格式 [A-Za-z0-9_.-]{1,128}） |
| `title` | VARCHAR(255) | 显示名（可选） |
| `description` | TEXT | 功能描述 |
| `enabled` | BOOLEAN | 是否启用 |
| `config` | TEXT(JSON) | `{ data_source_id, sql_template, parameters[], timeout, max_rows }` |
| 审计字段 | — | 继承 BasePO |

索引：`UNIQUE(service_id, name)`，`(service_id)`

| 工具 | name | description | 默认 config |
|------|------|-------------|-------------|
| SEARCH_METADATA | `search_metadata` | 系统定义 | `{ timeout: 30 }` |
| GET_TABLE_INFO | `get_table_info` | 系统定义 | `{ timeout: 30 }` |

### Annotations 映射规则

MCP 协议适配层在生成 `tools/list` 时计算，管理端 API 不返回。映射规则：

| 权限组合 | 生成的 annotations |
|----------|-------------------|
| 仅允许 SELECT | `readOnlyHint: true, destructiveHint: false, idempotentHint: true` |
| 允许 INSERT / UPDATE / DELETE | `destructiveHint: true, readOnlyHint: false` |
| 允许 DDL | `destructiveHint: true` |

SEARCH_METADATA 和 GET_TABLE_INFO 无权限配置，固定为 `{ readOnlyHint: true, destructiveHint: false, idempotentHint: true }`。

> **注（2026-08-02 更新）**：PARAMETERIZED_SQL 已移除 `sql_policy` 配置（模板由作者配置时编写，运行时仅注入参数值，无需操作权限限制）。其 annotations 待协议层实现时从模板静态分析（示例值渲染后分析操作类型）推导，不再基于权限组合。

### 模板引擎集成

Parameterized SQL 的 SQL 模板使用模板引擎（`com.dati.common.template`，见 US-5.5）解析和渲染。

**语法**：SQL 模板使用 `{{paramName}}` 占位语法（替代原来的 `:paramName`）。支持语法：
- `{{var}}` — 变量绑定为 `?` 占位符
- `{{#if var}}...{{/if}}` — 条件包含 SQL 片段（var 为 null 时跳过）
- `{{#where}}...{{/where}}` — 智能 WHERE 块（全部跳过时 WHERE 消失，首个 AND/OR 裁剪）
- Array（`IN ({{ids}})`）— 自动展开为 `?, ?, ...`

**默认值优先级**：`parameters[].default_value` 优先。执行层在调用 `SqlRenderer.render()` 前，先用 `default_value` 补齐缺失参数。模板引擎的 `{{var:default}}` 语法在 SQL 场景中不推荐使用。

**执行链路**：
```
MCP tools/call
  │
  ├─ 1. 参数补齐：用 parameters[].default_value 填充缺失参数
  │
  ├─ 2. parser.parse(sqlTemplate) → CompiledTemplate
  │
  ├─ 3. sqlRenderer.render(compiled, filledParams) → PreparedSql
  │
  ├─ 4. conn.prepareStatement(ps.sql())
  ├─ 5. for each binding: stmt.setObject(idx, binding.value())
  ├─ 6. stmt.executeQuery() / executeUpdate()
  │
  └─ 7. 记录审计日志（正式调用）/ 不记录（调试）
```

**调试复用**：US-07 的 Tool 调试验证走同一套解析+渲染链路。

### 安全设计

- 自定义 Tool 创建时，数据源选择列表限定为 data_scope 内的数据源
- 执行时由执行引擎进一步校验数据范围

### 验收标准

1. 新服务进入 Tools Tab，3 个预置工具默认显示为已启用
2. 关闭 SEARCH_METADATA，刷新页面后保持关闭状态
3. 配置 EXECUTE_SQL 权限为 SELECT + INSERT，前端 annotations 预览显示 `readOnlyHint: false, destructiveHint: true`
4. 创建自定义工具，name 格式不合法时实时提示
5. 创建同名自定义工具时报错「Tool 名称已被使用」
6. 删除自定义工具，确认弹窗展示后执行，列表不再显示
