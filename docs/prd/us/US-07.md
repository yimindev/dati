## US-07：调试 Tool 调用

### 使用场景

管理员在 Tool 配置页直接测试 Tool 的执行效果：输入参数 → 权限校验 → 写操作二次确认 → 看到真实执行结果。用于发布前自查 Tool 是否按预期工作。

### 交互流程

```
Tool 列表 → 点击某 Tool 行的 [测试] 按钮 → 弹出测试对话框

  测试对话框：
    ├─ 顶部：Tool 名称 + 类型
    ├─ 输入参数区：根据 Tool 的 inputSchema 动态渲染表单字段
    │    └─ 按类型渲染：String→文本框, Number→数字框, Boolean→开关, Date→日期选择器, Array→逗号分隔输入
    ├─ [执行测试] 按钮
    │    │
    │    ├─ 第一步：权限校验
    │    │    └─ 不通过 → 红色提示「当前 Tool 不允许执行此操作」
    │    │
    │    ├─ 第二步（写操作）：二次确认弹窗
    │    │    └─ 展示即将执行的 SQL 摘要 + 「确认执行」按钮
    │    │    └─ 取消 → 回到测试对话框
    │    │
    │    └─ 第三步：真实执行
    │         ├─ 成功 → 展示结果区域（JSON 格式化展示 / 表格展示）
    │         └─ 失败 → 展示错误信息（红色文本，代码块格式）
    │
    └─ [关闭]
```

### 异常与边界

- 超时：展示「执行超时（超过 XX 秒）」+ 建议调整超时配置
- 数据源不可用：展示「数据源连接失败：<原因>」
- SELECT 结果为空：正常展示空数组/空表格，不视为错误
- 参数校验失败：展示「参数 xxx 不符合类型要求」

### 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/v1/mcp-services/{id}/tools/{toolId}/test` | 调试验证。Body: `{ arguments, confirmed? }`。第一次调用不带 confirmed（权限/确认阶段），写操作权限通过后返回 `{ requiresConfirmation: true, sqlSummary }`。第二次带 `confirmed: true` 执行并返回结果 |

### 前端设计

- 测试对话框为 Modal，宽度较宽（展示 SQL 结果）
- SELECT 结果用表格展示（列名 + 数据行），超过 50 行截断并提示
- 写操作结果展示影响行数
- 错误信息用代码块格式（深色背景），保留原始错误
- 二次确认弹窗清晰展示 SQL 摘要

### 数据库设计

- 调试调用不产生审计日志（不是外部 Client 调用）
- 调试调用使用当前已保存的草稿配置（不走已发布快照），直接执行

### 安全设计

- 调试功能仅管理员可用（前端路由保护 + 后端接口鉴权）
- 调试调用真实数据源执行，SELECT 无需确认，写操作需二次确认
- 调试调用不记录到审计日志（避免污染正式调用统计）

### 验收标准

1. 测试 SELECT Tool，输入参数，点执行，直接展示查询结果表格
2. 测试只允许 SELECT 的 Tool，输入 DELETE SQL，权限校验拦截并提示
3. 测试允许 INSERT 的 Tool，输入 INSERT SQL，先弹确认框展示 SQL 摘要，确认后执行并展示影响行数
4. 数据源不可用时，提示连接失败原因
