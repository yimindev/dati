## US-10：删除 MCP 服务

### 使用场景

管理员删除一个 MCP 服务。系统展示级联删除影响清单，管理员确认后执行。

### 交互流程

```
触达方式：
  服务列表页 → 行尾的 [删除] 按钮
  服务详情页 → 基础信息 Tab 的 [删除] 按钮

删除确认弹窗：
  ├─ 标题：「确认删除服务」
  ├─ 服务名称展示
  ├─ 级联影响清单：
  │    ├─ Tools：X 个（列出名称）
  │    ├─ Resources：X 个（列出名称）
  │    ├─ Prompts：X 个（列出名称）
  │    ├─ Tokens：X 个（列出名称）
  │    └─ 调用日志：XX 条
  ├─ 警告文本：「以上资源将被永久删除，无法恢复」
  ├─ 确认输入：输入服务名称以确认（防止误操作）
  └─ [确认删除] / [取消]
```

### 异常与边界

- 服务处于已发布状态：同样可以删除，无需先停用
- 服务名称输入错误不匹配：「确认删除」按钮置灰
- 删除中网络错误：提示删除失败，可重试

### 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/v1/mcp-services/{id}/delete-preview` | 查询级联影响清单。返回：`{ tools: [...], resources: [...], prompts: [...], tokens: [...], auditLogCount: N }` |
| `DELETE` | `/v1/mcp-services/{id}` | 执行删除。级联删除关联的 Tool / Resource / Prompt / Token / 数据范围 / 审计日志。返回 `IdResponse` |

### 前端设计

- 删除确认弹窗为非 Modal 对话框，信息较多
- 级联清单用折叠列表或标签云展示
- 确认输入框实时校验，匹配才启用按钮
- 删除成功后跳转到服务列表页

### 数据库设计

- 各子表 `service_id` 均设外键 `ON DELETE CASCADE`，或在应用层逐表删除
- 不涉及新表

### 安全设计

- 仅管理员可删除
- 需要输入服务名称二次确认，防止误操作

### 验收标准

1. 点击删除，弹窗展示级联影响清单（Tool/Resource/Prompt/Token 数量及名称，日志条数）
2. 输入服务名称匹配后，确认删除按钮可用
3. 确认删除，服务从列表消失，关联的所有数据清除
4. 输入错误名称时，确认删除按钮不可点击
