# 快速上手

你可以通过以下两种方式快速上手 DatI：
- **方式一：Agent 自动化操作** —— 使用 `dati-ops` skill，通过对话直接让 AI 助手自动完成数据源接入与服务发布；
- **方式二：Web 控制台可视化操作** —— 在浏览器控制台中逐步完成数据源接入、主题划定与 MCP 服务发布。

---

## 方式一：使用 dati-ops 技能自动化操作

DatI 原生提供了遵循 [Agent Skills 开放标准](https://agentskills.io) 的自动化运维技能 **`dati-ops`**。你可以直接将该技能挂载到 AI 编码助手（如 OpenCode、Claude Code、Antigravity 等），通过自然语言下达指令，让 Agent 全自动完成数据源接入、语义建模和 MCP 服务发布。

### 1. 前置条件与 API Key 获取

使用 `dati-ops` 技能前，需获取访问凭据并建议配置为环境变量：

1. **获取 API Key**：登录 DatI 平台后，点击右上角 **用户头像 ->「API Key 管理」**，点击「新建 API Key」即可生成；
2. **配置连接参数（推荐方式）**：在终端或环境配置文件（如 `~/.zshrc`、`~/.bashrc` 或工作区 `.env`）中导出环境变量：
   ```bash
   export DATI_BASE_URL="http://localhost:8085"  # DatI 服务地址（默认为 http://localhost:8085）
   export DATI_API_KEY="sk_your_api_key_here"    # 生成的 API Key
   ```
   配置环境变量后，Agent 在执行技能时会自动读取，安全且无需在每次对话中重复传递。

> **提示**：若未配置环境变量，也可在向 Agent 发送对话指令时直接提供 `baseUrl` 与 `apiKey`（例如：“*在 `http://localhost:8085` 环境下，使用 apiKey: `sk_...` 帮我接入...*”）。

### 2. 技能获取与挂载方式

* **本地开发环境**：直接引用代码仓库中的 `skills/dati-ops/SKILL.md`；
* **远程/托管环境**：可通过 <a :href="$frontmatter.skillUrl" target="_blank" rel="noopener noreferrer">dati-ops 技能仓库地址</a>（或访问 <a :href="$frontmatter.skillsUrl" target="_blank" rel="noopener noreferrer">Skills 目录</a>）获取完整的技能定义与工具脚本。

### 3. 一句话自动化操作

直接向已加载 `dati-ops` 技能的 Agent 发送业务指令：

> *“帮我接入本地 MySQL 订单数据库（root/123456@localhost:3306/shop），将 orders 和 order_items 表同步进系统，创建「电商订单分析」主题并发布一个 MCP 服务。”*

Agent 将自动查询 OpenAPI 接口契约，自动校验连接、批量同步表列、抽取字典值、建立主题与术语，并一键发布上线可用服务！

## 方式二：Web 控制台可视化操作

如果你希望在图形界面中手动配置，可按以下流程逐步操作：

### 1. 接入数据源与元数据抽取

进入 **「数据源管理」** 页面，点击 **「创建数据源」**：

1. 填写数据库连接信息（支持 MySQL、PostgreSQL、ClickHouse、Doris 等），点击 **「测试连接」** 验证连通性；
2. 保存后，在数据源详情页点击 **「添加表」** 批量导入需要分析的物理表；
3. 对导入的表点击 **「同步列」** 获取最新的表结构。

::: tip 核心机制：为什么需要「抽取字典值」？
大模型仅凭物理字段名（如 `status`、`pay_type`）很难准确推断具体业务枚举。
在列详情中对枚举字段点击 **「抽取字典值」**，DatI 会自动探查实际数据并记录字段字典值（例如 `1 -> 待支付`、`2 -> 已完成`）。这些信息会在语义检索时提供给 Agent，大幅提升 SQL 生成的准确率。
:::

### 2. 建立业务主题与术语关联

进入 **「主题管理」** 页面，点击 **「创建主题」**：

1. **创建主题**：选择关联的数据源，填写主题名称（如「电商订单分析」、「财务核算」）与业务描述；
2. **添加表（限定数据范围）**：进入主题详情页的「数据表」列表，点击 **「添加表」**，从数据源中勾选当前主题真正关心的几张核心业务表（例如只挑选 `orders` 与 `order_items` 表）；
3. **定义业务术语与关联 (Terms)**：切换到「业务术语」列表，点击 **「新建术语」**，填写业务日常使用的指标或黑话（例如 `GMV`、`客单价`、`有效活跃用户`），并可关联到数据表或字段（以便匹配到术语时可以返回相应 schema）。

::: tip 核心机制：为什么需要主题来「限定表范围」与「语义建模」？
- **精准收敛表范围**：一个企业数据源通常有几十甚至上千张表（包含系统表、日志表、敏感表等）。如果把整个数据库直接暴露给大模型，不仅消耗巨量 Prompt Token，还极易引发选表幻觉。主题将表范围精准收敛到具体分析场景所需的几张表，既降本又提效；
- **业务语言与物理结构解耦**：用户提问使用的是业务语言（如“查下本月 GMV”），而底层表字段可能是 `total_amount`。通过术语关联，Agent 通过语义检索即可精准对齐业务指标与物理字段，告别字段猜测。
:::

### 3. 构建与发布 MCP 服务

进入 **「MCP 服务」** 页面，点击 **「新建服务」**：

1. **基本信息**：填写服务名称和唯一服务标识（`service_code`，作为 MCP 端点 URL 路径）；
2. **配置数据范围 (Data Scope)**：选择该服务允许访问的数据源与业务主题；
3. **配置工具 (Tools)**：
   - **预置工具**：开启 `inspect_schema`（元数据探查）与 `execute_sql`（安全只读 SQL 执行）；
   - **自定义参数化工具**：编写基于模板引擎的参数化 SQL，使用 `{{user_id}}` 等上下文变量实现安全防越权查询；
4. **发布服务**：确认无误后点击 **「发布」**。

::: tip 核心机制：数据范围隔离与版本快照
- **数据范围隔离**：MCP 服务只能访问在数据范围中明确授权的数据源与主题，未授权的库表对 Agent 物理不可见。
- **草稿与快照发布**：服务的修改会在草稿区生效，不会影响线上运行；点击「发布变更」后会生成不可变快照（Snapshot），新版本即时生效，且支持随时一键回滚到历史版本。
:::

### 4. 在 Agent 客户端中接入

DatI 采用标准 **Model Context Protocol (Streamable HTTP)** 协议暴露服务端点。服务发布后，在服务详情页右侧的 **「接入配置」卡片** 中可一键复制客户端 JSON 配置。

#### 客户端配置示例

以 **OpenCode**、**Claude Code** 或 **Cursor** 为例，在 MCP 配置文件中添加：

```json
{
  "mcpServers": {
    "dati-order-service": {
      "url": "http://localhost:8085/order-analysis/mcp",
      "headers": {
        "Authorization": "Bearer <YOUR_API_KEY>"
      }
    }
  }
}
```

::: tip API Key 凭据获取
将配置中的 `<YOUR_API_KEY>` 替换为实际凭据。可直接点击详情页接入卡片底部的 **「前往管理 API Key」** 快捷创建，或通过页面右上角 **用户头像 ->「API Key 管理」** 进入。
:::

配置完成后，Agent 即可在对话中自动发现并调用该 MCP 服务下的元数据检索与数据查询工具。
